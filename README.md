# Простой Telegram-бот для учета трат

Бот работает без ИИ. Траты хранятся локально в SQLite; отдельный раздел облигаций получает публичные рыночные данные MOEX ISS.

## Формат записи

Одна трата:

```text
еда 500
```

Несколько трат — строго через запятую:

```text
еда 500, супермаркеты 2300, транспорт 250
```

Первое слово — категория, второе — место, остальные слова — комментарий, последнее число — сумма:

```text
еда Пятёрочка хлеб и молоко 850
еда Кафе обед с Колей 850
```

Если места нет, по-прежнему можно написать `еда 500`. Старым записям место автоматически не назначается. Регистр категории и места не влияет на группировку.

Без даты трата записывается на текущий учётный день. Он заканчивается в 04:00 по часовому поясу пользователя: например, покупка в 02:30 первого октября относится к 30 сентября. Явно указанная дата остаётся приоритетной. Дату можно поставить в начале сообщения — тогда она применяется ко всем тратам:

```text
23.09 еда 500, транспорт 250
23.09.2026 еда 500, транспорт 250
```

Для разных дат в одном сообщении дата ставится после каждой траты:

```text
еда 500 22.09, транспорт 250 23.09
```

Регистр категории не имеет значения: `транспорт`, `Транспорт` и `ТРАНСПОРТ` сохраняются как одна категория «Транспорт».

Флаг `ЕЖЕМЕСЯЧНО` распределяет сумму по всем дням выбранного месяца:

```text
Зал 2500 ЕЖЕМЕСЯЧНО
23.09 Зал 2500 ЕЖЕМЕСЯЧНО
```

Сумма делится с точностью до копейки, а `/undo` удаляет всё распределение целиком.

## Запуск

1. Создай бота через `@BotFather` в Telegram и получи токен.
2. Запусти:

```bash
export TELEGRAM_BOT_TOKEN="токен_от_BotFather"
export ALLOWED_TELEGRAM_USER_IDS="563057258,656675199"
export BOT_TIMEZONE="Asia/Tomsk"
python3 -m pip install -r requirements.txt
python3 bot.py
```

Процесс должен оставаться запущенным, чтобы бот отвечал и присылал сообщения по расписанию.

## Команды

- `/start` — начало работы и подсказка;
- `/budget 70000` — месячный бюджет; `/status` — траты, бюджет и дневной/недельный остаток по запросу;
- `/salary 100000` — месячная зарплата; `/salary 0` убирает её;
- `/income подработка 5000` — другой доход; `/income 23.09 подработка 5000` — доход за дату;
- `/incomes` — список доходов; `/income_delete ID` — удалить ошибочную запись;
- `/refund 123 800` — возврат по номеру покупки из `/history` (исходная трата остаётся); `/refund Еда 800` — возврат без привязки;
- `/goal 20000` — месячная цель накоплений; `/goal 0` — убрать;
- `/free` — сколько свободно до конца месяца после цели и планов;
- `/plan 15.10 стоматолог 15000` — планируемая трата; `/plans` и `/plan_delete ID` — список и удаление;
- `/report` — с 1 октября 2026 года отчёт за текущий календарный месяц (с 1-го по последнее число), с кнопками переключения месяцев; до октября старый вид отчёта сохраняется;
- `/report 10.2026` — отчёт за конкретный календарный месяц;
- `/report 01.09 15.09` — отчёт за произвольный период;
- `/category Еда` — подробности по категории за текущий месяц: суммы по местам, доли, покупки и средний чек; `/category Еда 09.2026` — за другой месяц;
- `/place Пилад` — траты в этом месте за текущий месяц и всё время, по всем категориям; `/place Библио вендинг 09.2026` — выбрать другой месяц;
- `/aliases` — псевдонимы мест; `/alias мак = Вкусно-и-точка` — добавить или изменить; `/alias_delete мак` — удалить. Для каждого пользователя правила свои, старые записи в базе не переписываются;
- `/compare` — сравнение текущей и прошлой недели;
- `/compare_months` — сравнение текущего месяца с прошлым;
- `/week` — итог завершившейся недели;
- `/history` — последние покупки; покупку можно открыть и посмотреть место и комментарий;
- `/limit Еда 20000` — месячный лимит категории;
- `/limits` — показать лимиты;
- `/limit_delete Еда` — удалить лимит;
- `/recurring add 5 Интернет Провайдер домашний 900` — ежемесячный автоплатёж 5-го числа;
- `/recurring` — список и удаление регулярных платежей;
- `/favorite add Еда Кафе бизнес-ланч 600` — добавить быструю трату;
- `/favorites` — кнопки избранных трат;
- `/search такси` — поиск по местам и комментариям;
- `/export` — выгрузка всех трат в CSV;
- `/import` — загрузка CSV из экспорта: отправь CSV-документ с подписью `/import` (один файл не импортируется повторно);
- `/settings` — показать настройки; `/settings cutoff 4`, `/settings reminders 20 22 0`, `/settings morning 10`, `/settings profit 10`, `/settings timezone Asia/Tomsk` — изменить их;
- `/undo` — удалить последнюю запись;
- `/zero` — отметить день без трат;
- `/help` — показать формат ввода.

## Облигации

Раздел не изменяет траты, бюджет, зарплату и старые отчёты. Для каждого разрешённого
пользователя отдельный портфель; инвестиционные команды работают только в личном чате.
Пока поддерживается один счёт Альфы на пользователя, рублёвые облигации и длинные позиции.

Отправь брокерский `.xlsx` Альфа-Инвестиций с подписью `/invest_import`
(`/import` с XLSX тоже работает). Желательно выгрузить период с открытия счёта.
Данные хранятся в той же постоянной SQLite, в отдельных таблицах. XLSX целиком и имя
клиента не сохраняются. Новые отчёты обновляют снимок позиций; одинаковые файлы и сделки
в пересекающихся периодах не добавляются дважды. Конфликтующие сделки/другой счёт отклоняются.
Более ранний отчёт может дополнить историю уже загруженного портфеля.

- `облигации` или `/invest` — короткая инструкция и кнопки;
- `мои облигации` или `/portfolio` — текущая стоимость и список;
- `сколько заработал` или `/profit` — короткий общий результат; детали по кнопке;
- `/pnl` — короткий итоговый PNL по всем облигациям: купоны + результат закрытых сделок
  + изменение стоимости оставшихся с НКД. Комиссии уже учтены, повторно не вычитаются.
  Если история/котировки/сопоставление выплат неполные, общий итог недоступен, отдельно
  показывается результат только учтённых выпусков. Котировки актуализируются через тот же
  кэш MOEX, фактические сделки и выплаты — по последнему импортированному отчёту;
- `/forecast 31.12.2026` — купоны, возврат номинала и купонный доход до даты включительно;
- `/maturity` — выплаты и прибыль с первоначальной покупки до погашения каждого выпуска;
- `/bond Брусника` или `/bond RU000A10C8F3` — подробности, последние 12 сделок, ближайшие выплаты;
  если подходят несколько выпусков, бот предлагает кнопки;
- `/payments` — календарь на следующие 90 дней.

Также работают `до 31.12.2026`, `до погашения`, `ближайшие выплаты`.
Пользователям с импортированным портфелем в 10:00 по их часовому поясу приходит
отдельная ежедневная сводка: стоимость бумаг с НКД, изменение оценки относительно
предыдущей сохранённой сводки, отдельно рыночная стоимость без НКД и изменение НКД,
а также общий результат с покупки после комиссий, если он рассчитан полностью.
Эту же сводку можно запросить в любое время: `/portfolio_day`, фразой
`сводка портфеля` / `изменение портфеля` или кнопкой «Изменение за день».
Ручной запрос не заменяет сохранённую утреннюю оценку и не отменяет отправку в 10:00.
Снимки хранятся в постоянной SQLite отдельно для каждого пользователя. После первого
запуска создаётся исходная оценка; после изменения истории в XLSX сравнение сбрасывается,
чтобы загрузка старых покупок/выплат не выглядела как доход за сутки. В этом случае
купонные поступления, комиссии сделок и возвраты номинала показываются явно за всю
загруженную историю, не за день. Новые выплаты не считаются фактическими без XLSX.
Если после даты отчёта по графику были выплаты, сводка предупреждает, что падение
оценки из-за НКД/номинала не обязательно является убытком. При отсутствии свежих цен
сравнение пропускается с объяснением. Существующие утренние сообщения и настройки
напоминаний не меняются; сводка портфеля имеет отдельное время 10:00.
Итог отдельно показывает изменение чистой цены бумаг (включая закрытые/погашенные
выпуски), фактические купоны, изменение накопленных процентов и комиссии. Комиссии
вычитаются один раз. Возврат номинала не считается доходом: он сопоставляется с
затратами на покупку. Погашенные выпуски из сделок сохраняются даже при отсутствии
в конечном списке позиций; списание сверяется с фактическим возвратом и графиком MOEX.
Повторный импорт того же XLSX после исправления парсера может дополнить нормализованную
историю, сохраняя ранее импортированные сделки и выплаты без дублей.
Старые команды сохранены. Расчёт идёт отдельно от обработки сообщений: бот сразу
отвечает «Считаю…», а траты и другие команды не ждут MOEX. Повторный расчёт того же
пользователя не запускается, пока предыдущий не завершён.

### Источники и расчёты

Публичный [MOEX ISS](https://www.moex.com/a8531) не требует банковской авторизации и
предоставляет бесплатные котировки с задержкой. Запросы:

```text
/iss/securities/{ISIN}.json
/iss/engines/stock/markets/bonds/securities/{ISIN}.json
/iss/securities/{ISIN}/bondization.json?limit=unlimited
```

Выбирается основной режим торгов. Если последней цены нет, используется предыдущая
цена с её датой. Котировки кэшируются на 15 минут, описание и полный календарь выплат —
на сутки. При сбое API сохранённые данные показываются с предупреждением, отсутствующие
данные не заменяются нулями. Указывается дата котировки и дата расчётов для НКД.

Цена облигации в процентах переводится в рубли по оставшемуся номиналу; затем добавляется
НКД и умножается на количество. Сумма сделки в отчёте Альфы **уже включает НКД** — повторно
он не прибавляется. Комиссии включены в стоимость покупки, вычтены из продажи.
Себестоимость продаж распределяется FIFO. Общий результат = продажи + полученные купоны
+ возврат номинала + текущая стоимость оставшихся бумаг − покупки − комиссии.

Прогноз начинается **после конца последнего брокерского отчёта**, чтобы не выдавать ещё
не подтверждённые выплаты за реальные. Список фактических купонов обновляется только
новым отчётом, а не календарём MOEX. Прошедшие плановые даты после отчёта остаются прогнозом.
«Всего на счёт» включает возврат капитала: это не прибыль. Купонный доход за период =
выплачиваемые купоны + НКД на конечную дату − НКД на начальную дату. Будущий НКД вычисляется
по известным купонным периодам; после погашения он равен нулю. Будущая цена продажи
не прогнозируется. При удержании до погашения итог = все исторические и будущие денежные
поступления − стоимость покупок с комиссиями.

Налоги, реинвестирование и новые сделки не моделируются. Неизвестные купоны не продолжаются
по предыдущей ставке. Оферты/call/put делают долгосрочный прогноз условным. Выплаты по
графику не гарантированы. При неполной начальной истории, пропусках отчётов, неучтённых
изменениях количества/неторговых операциях показываются доступные данные, но не выдуманная
прибыль. При исторической амортизации общий денежный результат доступен, если история и
количество сходятся, но FIFO-разбивка и оставшаяся себестоимость требуют отдельной обработки.
Акции, фонды и РЕПО в раздел облигаций не включаются.

Для приватного разового переноса уже предоставленного отчёта администратор может задать
`INVESTMENT_BOOTSTRAP_GZIP_BASE64`: gzip/base64 JSON с `chat_id`, `sha256` исходного XLSX и
нормализованным `report` из `investments.parse_alfa`. Импорт разрешён только для ID из
allowlist, идемпотентен по хешу и не изменяет таблицу трат. После успешного переноса переменную
следует удалить. Отчёты, персональные данные и котировки конкретного портфеля не коммитятся.

Проверка: `python3 -m unittest -q`.

Если бюджет задан, каждое утро в 10:00 бот показывает доступный бюджет отдельным сообщением. Если не задан, он напоминает об этом только по понедельникам в 10:00. Зарплата хранится отдельно для каждого пользователя; `/report` показывает зарплату и разницу между ней и тратами текущего месяца на сегодня. При заданной зарплате в 10:00 бот отдельно присылает итог за завершившийся учётный день: зарплата за месяц, делённая на число дней того месяца, минус траты дня. В 20:00 бот напоминает записать расходы. Если пользователь не ответил и не нажал «Сегодня без трат», бот повторяет напоминание в 22:00 и 00:00.

По понедельникам в 11:00 бот присылает итог прошлой недели. Зарплата учитывается с даты изменения, поэтому старые дневные итоги не пересчитываются по новой ставке. Другие доходы добавляются к прибыли в день получения. Возврат сохраняется отдельной отрицательной записью и уменьшает траты. Если за текущую неделю категория превысила более чем вдвое обычный недельный расход за предыдущие четыре недели, бот отмечает это после записи траты. Настройки времени индивидуальны для каждого пользователя.

Начиная с октября `/report` привязан к календарным границам месяца, а не ко всей истории трат. Распределённые флагом `ЕЖЕМЕСЯЧНО` суммы учитываются за весь выбранный месяц, включая ещё не наступившие дни текущего месяца. Старые данные и отчёты за произвольный период остаются доступны.

Кнопка «Уже всё записал» останавливает дальнейшие напоминания на этот день и удаляет сообщение с кнопками, не изменяя список трат.

В `/history` у каждой покупки есть кнопки редактирования и удаления. После нажатия
«Редактировать» нужно отправить исправленную покупку целиком; `/cancel` отменяет действие.

Регулярный платёж создаёт одну обычную трату в заданный день каждого месяца. Флаг
`ЕЖЕМЕСЯЧНО` работает по-прежнему и распределяет одну сумму по всем дням месяца.

## Деплой в Railway

Production разворачивается в Railway из ветки `main` этого репозитория через `Dockerfile`.
Для сохранения базы между перезапусками сервису нужен volume, подключенный к `/data`.

Переменные окружения:

- `TELEGRAM_BOT_TOKEN` — секретный токен от BotFather;
- `ALLOWED_TELEGRAM_USER_IDS` — Telegram ID пользователей через запятую; данные каждого хранятся отдельно;
- `BOT_TIMEZONE=Asia/Tomsk`;
- `MORNING_HOUR=10`;
- `DATABASE_PATH=/data/expenses.db`.
